# Adding a packet (IN or OUT)

An IN packet is something the **client sends** to the server (e.g. use skill, move, click). An OUT packet is something the **server sends** to the client (e.g. update target, spawn a mob).

## Shared base

- `src/core/enum/PacketHeaderEnum.ts` — a single object `{ NAME: 0xHEX, ... }` mapping name → header (1 byte). Add the new entry here first.
- `src/core/interface/networking/packets/packet/Packet.ts` — abstract base class (`header`, `subHeader`, `size`, `name`, `sequenced`, optional `validator`).
- `src/core/interface/networking/packets/Packets.ts` — central registry: `Map<number, PacketMapValue<T>>` used by the dispatcher to recognize **incoming** packets. Each entry has `createPacket`, `createHandler` and `phases` (`LOGIN_PHASES`, `GAME_PHASES` or `EVERY_PHASE` — restricts which connection phase accepts the packet).

**Common gap to forget**: creating the packet + handler + validator without adding the matching entry in `Packets.ts`. Without it the dispatcher never recognizes the packet, even with everything else implemented. Always double-check this file before considering the task done.

## IN packet

Structure: `src/core/interface/networking/packets/packet/in/<name>/`, with 3 files (real example: `skillUse/`):

1. `<Name>Packet.ts` — extends `PacketIn`, implements `unpack(buffer: Buffer): this` reading from `this.bufferReader`:
   ```ts
   export default class SkillUsePacket extends PacketIn {
       private skillNum: number;
       private targetVirtualId: number;
       constructor({ skillNum, targetVirtualId }: {...}) {
           super({ header: PacketHeaderEnum.SKILL_USE, name: 'SkillUsePacket', size: 5, validator: SkillUsePacketValidator });
           ...
       }
       unpack(buffer: Buffer) {
           this.bufferReader.setBuffer(buffer);
           this.skillNum = this.bufferReader.readUInt32LE();
           this.targetVirtualId = this.bufferReader.readUInt32LE();
           this.validate(); // triggers the validator — not automatic, must be called explicitly
           return this;
       }
   }
   ```
2. `<Name>PacketValidator.ts` — extends `PacketValidator<T>` (which extends `FluentValidator`, in `src/core/interface/networking/packets/PacketValidator.ts`):
   ```ts
   build() {
       this.createRule(value, 'field').isRequired().isNumber().isGreaterThanOrEqual(0).build();
   }
   ```
3. `<Name>PacketHandler.ts` — extends `PacketHandler<T>` (`abstract execute(connection: Connection, packet: T): Promise<void>`), injects dependencies from the container cradle (`{ logger, someService }`), resolves `connection.getPlayer()`, validates (`packet.isValid()` or similar) and calls the domain/service layer. Closes the connection on anomalous cases with `connection.close()`.

## OUT packet

Structure: `src/core/interface/networking/packets/packet/out/<name>/`.

- `<Name>Packet.ts` — extends `PacketOut`, implements `pack(): Buffer` writing to `this.bufferWriter`:
  ```ts
  /**
   * @packet
   * @type Out
   * @name TargetUpdatedPacket
   * @header 0x3f
   * @size 6
   * @description Used to send the target to client.
   * @fields
   *   - {byte} header 1 Packet header
   *   - {number} virtualId 4 virtualId of the target entity
   *   - {byte} healthPercentage 1 indicates the percent of target entity health
   */
  export default class TargetUpdatedPacket extends PacketOut {
      constructor({ virtualId, healthPercentage }: {...}) {
          super({ header: PacketHeaderEnum.TARGET_UPDATED, name: 'TargetUpdatedPacket', size: 6 });
          ...
      }
      pack() {
          this.bufferWriter.writeUint32LE(this.virtualId);
          this.bufferWriter.writeUint8(this.healthPercentage);
          return this.bufferWriter.getBuffer();
      }
  }
  ```
- **The `@packet` JSDoc block is mandatory** for OUT packets — it's the only source for `docs/packets.md` (generated by `tools/doc/docGenerator.js`, which only scans `packet/out/**`). IN packets are not documented by that tool.
- OUT packets **do not go through `Packets.ts`** (that map is only for routing received packets). They're instantiated and sent from wherever it makes sense in the domain, typically a method on `Player` (`src/core/domain/entities/game/player/Player.ts`):
  ```ts
  sendTargetUpdated(target?: Character) {
      this.connection?.send(new TargetUpdatedPacket({ virtualId: target?.getVirtualId() ?? 0, healthPercentage: ... }));
  }
  ```

## Step by step

1. Add the header in `src/core/enum/PacketHeaderEnum.ts`.
2. Create the folder `packet/in/<name>/` or `packet/out/<name>/`.
3. IN: create Packet + Validator + Handler (3 files, see above).
4. OUT: create the Packet with the `@packet` JSDoc block; trigger it via `connection.send(new MyPacket({...}))`.
5. For IN: **register it in `src/core/interface/networking/packets/Packets.ts`** (import + entry in the Map with `createPacket`, `createHandler`, `phases`).
6. If the handler injects new dependencies, register them in the `Container.ts` of the corresponding server (`src/auth/Container.ts` or `src/game/Container.ts`) — see [CLAUDE.md](../../../CLAUDE.md#dependency-injection-awilix).
7. If you created or changed an OUT packet, run `npm run generate:doc` to refresh `docs/packets.md`.
8. Write tests: a unit test for the handler/validator (mock dependencies with sinon) and, if the flow depends on a real socket, an integration test (see the `testing-conventions` skill).
